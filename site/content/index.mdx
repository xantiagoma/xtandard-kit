```sh
bun add @xtandard/kit
```

You don't install the kit to use an xtandard product: each product depends on it directly. You need
it when you build an xtandard-style product, or when you work on one. It is **one package** with
subpath exports, and every database client, framework and build tool is an **optional peer
dependency**, loaded only by the subpath that needs it.

## What's inside

<CardGrid>
  <Card title="Storage" icon="seti:db">
    The KV contract with watch and compare-and-swap, ten drivers, and the conformance suite every
    product runs against its own drivers.
  </Card>
  <Card title="Server" icon="setting">
    Auth and authorization providers, hooks, panel serving, the router and OpenAPI generator,
    scoped tokens, framework adapters and CLI plumbing.
  </Card>
  <Card title="UI kit" icon="laptop">
    The React admin shell, primitives, theme store, API client and the embed factory, compiled ESM
    with a Tailwind stylesheet.
  </Card>
  <Card title="Tooling" icon="puzzle">
    The `xtandard-kit` bin (embed CSS scoping, API-surface gate), config factories, this docs-site
    tooling and the reusable GitHub workflows.
  </Card>
</CardGrid>
